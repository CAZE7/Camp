# Risk Register — Camp (Elektrikplaner)

**Stand:** 2026-11-04  
**Status:** Verbindlich (Erstfassung, lebendes Dokument)  
**Verantwortlich:** Safety Engineering (Einträge), QE (Verifikation), Product Owner (Akzeptanz von Restrisiken)  
**Übergeordnet:** `docs/safety/SAFETY-PLAN.md`, `docs/safety/SAFETY-CASE.md`, `docs/engineering/ENGINEERING-CONSTITUTION.md`  
**Methode:** Fehlerbaumanalyse + System-Sicherheitsanalyse; vereinfachte Risikopriorisierung nach Schwere (S1–S4) und Wahrscheinlichkeit (E1–E4) mit RPN = S × E **nur für sicherheitskritische Risiken (Klasse S)**. Für Nicht-S-Klassen (D, F, P, Q, UX) ist RPN nicht anwendbar (keine Schwere-Klasse S definiert) und wird als "—" ausgewiesen. Dies ist **keine vollständige klassische FMEA** (keine systematische Erkennbarkeitsbewertung), sondern eine vereinfachte Risikopriorisierung zur Vergleichbarmachung sicherheitskritischer Risiken.

---

## 1. Legende

| Spalte                              | Bedeutung                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| **ID**                              | Eindeutige Risiko-ID (R-001 …)                                                  |
| **Gefährdung / Top-Ereignis**       | Was kann schiefgehen, welche Schädigung entsteht                                |
| **Ursache / betroffene Komponente** | Woher kommt das Risiko, welcher Code / welche Datei                             |
| **S**                               | Schwere (S1 katastrophal … S4 niedrig)                                          |
| **E**                               | Eintrittswahrscheinlichkeit (E1 sehr wahrscheinlich … E4 sehr unwahrscheinlich) |
| **RPN**                             | Risikoprioritätszahl = S × E                                                    |
| **Klasse**                          | S = sicherheitskritisch, F = funktional, D = Daten, P = Prozess, Q = Qualität   |
| **Maßnahme**                        | Getroffene oder geplante technische/organisatorische Maßnahme                   |
| **Verifikation**                    | Test, Property, Architekturtest, Referenzberechnung, Review                     |
| **Status**                          | Offen / In Behandlung / Behandelt (mit Nachweis) / Akzeptiert als Restrisiko    |
| **Verantwortlich**                  | Rolle                                                                           |
| **Datum**                           | Letzte Änderung                                                                 |

**Schwere:**

- S1: Katastrophal (Brand, Stromschlag, Personengefahr)
- S2: Schwer (falsche Dimensionierung, Fehlfunktion)
- S3: Mittel (irreführender Befund, Anzeigefehler)
- S4: Niedrig (Komfort, kosmetisch)

**Wahrscheinlichkeit:**

- E1: Sehr wahrscheinlich
- E2: Möglich
- E3: Unwahrscheinlich
- E4: Sehr unwahrscheinlich

**Behandlungspriorität:** RPN ≥ 12 hoch (Release blockierend), 6–11 mittel, ≤ 5 niedrig.

## 4. Prozess zur Pflege des Risk Registers

1. **Erfassung:** Jede neue Gefährdung wird als Eintrag mit ID, Schwere, Wahrscheinlichkeit, RPN erfasst.
2. **Behandlung:** Für jeden Eintrag wird eine Maßnahme definiert, umgesetzt und verifiziert.
3. **Verifikation:** Der Verifikationsnachweis wird gemäß `SAFETY-CASE.md` §4 erbracht und referenziert.
4. **Statuswechsel:** „Behandelt“ erst mit Nachweis; „Akzeptiert als Restrisiko“ nur mit Begründung und Product-Owner-Freigabe.
5. **Review:** Bei jedem Release und bei jeder Änderung sicherheitskritischer Dateien wird das Register neu bewertet. Einträge werden nie still gelöscht, sondern auf „geschlossen“ mit Datum gesetzt.
6. **Blockierung:** Einträge mit RPN ≥ 12 und Status ≠ „Behandelt (mit Nachweis)“ blockieren den Release.
